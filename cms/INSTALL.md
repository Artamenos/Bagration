# Установка CMS на Timeweb Year

CMS пока нельзя считать принятой на production без серверных проверок ниже. Код не содержит реальных паролей. Создание базы и первоначальная настройка выполняются владельцем аккаунта; публикация исходников сама по себе админку не активирует.

1. В Timeweb создать одну MySQL 8 базу и отдельного пользователя этой базы. У поддержки подтвердить размещение сервера и базы в России. Выбрать актуальную поддерживаемую PHP-версию не ниже 8.2. В настройках PHP включить GD, PDO MySQL, OpenSSL, mbstring, fileinfo; upload_max_filesize минимум 8M, post_max_size минимум 10M. Отключить display_errors.
2. Собрать `npm run build:production`. PHP-файлы попадут в `out/admin` и `out/preview`. Выполнить обычную доставку релиза через GitHub Actions и существующий скрипт. Пока конфигурации нет, публичный сайт показывает встроенный контент.
3. В SSH создать постоянные каталоги:

```sh
mkdir -p "$HOME/Bagration/shared/content" "$HOME/Bagration/shared/media"
chmod 700 "$HOME/Bagration/shared"
chmod 755 "$HOME/Bagration/shared/content" "$HOME/Bagration/shared/media"
cp "$HOME/Bagration/public_html/admin/config.example.php" "$HOME/Bagration/shared/config.php"
chmod 600 "$HOME/Bagration/shared/config.php"
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

4. Через редактор Timeweb заполнить `shared/config.php`: имя базы в DSN, пользователь, пароль и сгенерированный ключ. Секреты вводить только в этот файл. Не отправлять их в чат, GitHub или аргументы команд.
5. Перед миграцией создать резервную копию через Timeweb. Затем выполнить:

```sh
php "$HOME/Bagration/public_html/admin/cli.php" check
php "$HOME/Bagration/public_html/admin/test.php"
php "$HOME/Bagration/public_html/admin/cli.php" install
php "$HOME/Bagration/public_html/admin/cli.php" add-admin admin-01
sh "$HOME/Bagration/timeweb-sync-production.sh"
```

Пароль минимум 16 символов вводится скрыто. Полученный TOTP-секрет вручную добавить в приложение-аутентификатор: SHA1, 6 цифр, 30 секунд. Сохранить его в защищённом менеджере паролей; это доступ к аккаунту. Повторить создание для admin-02/admin-03 при необходимости. Общие пароли запрещены.

6. Открыть `/admin/`. Создать черновик, сохранить, сформировать предпросмотр, открыть ссылку с телефона и опубликовать. Предпросмотр — отдельное представление текста и фотографии, а не точная копия карусели сайта. Его ссылка является временным доступом к черновику на час; не передавать посторонним. Предпросмотры удаляются при создании новых ссылок после истечения срока.
7. В браузере проверить `/content/current.json`, новые новости и выделение событий календаря. Обновления видны после перезагрузки страницы. Снятие всех новостей с публикации скрывает карусель. Для новостей допускается три и более записей; короткие заголовки и описания лучше помещаются в существующий дизайн.

## Проверки перед запуском

- Неверный пароль/TOTP отклоняется; повторное использование кода отклоняется. После пяти неудач учётная запись временно блокируется. Общий лимит 30 попыток за 5 минут защищает от перебора разных логинов.
- Проверить выход, истечение сессии и отзыв: `php "$HOME/Bagration/public_html/admin/cli.php" disable-admin admin-02`. Отзыв завершает доступ со всех устройств при следующем запросе. Сброс пароля — отзыв старой записи и создание новой служебной учётной записи.
- Два администратора одновременно открывают запись: сохранение устаревшего черновика должно отклоняться.
- Отправка без CSRF-токена отклоняется. `/admin/runtime.php`, `/admin/schema.sql`, `/admin/seed.json`, `/admin/cli.php`, `/preview/runtime.php` должны возвращать 403. HTTPS обязателен.
- PNG/JPEG/WebP перекодируются в JPEG; проверить файл свыше 8 МБ, SVG и PHP — должны отклоняться.
- Проверить историю: восстановление меняет только черновик, публикация выполняется отдельно. Если запись в MySQL прошла, а генерация JSON завершилась ошибкой, исправить права/свободное место и выполнить `php "$HOME/Bagration/public_html/admin/cli.php" snapshot`.
- Повторный деплой сохраняет медиа, JSON и доступ к админке. Неполадки MySQL не должны мешать чтению уже опубликованного JSON.
- В тестовой базе проверить восстановление из копии Timeweb вместе с каталогами shared; исходную рабочую базу ради проверки не перезаписывать. Из резервной копии отдельно восстановить ключ шифрования, иначе TOTP-секреты не расшифруются.

## Эксплуатация

Timeweb выполняет ночное резервное копирование. Перед изменением схемы — ручная копия. Раз в месяц скачивать зашифрованную резервную копию в отдельное безопасное место и проверять восстановление. Владелец проверяет доступы при смене сотрудников и сразу отзывает скомпрометированные.

В панели Timeweb включить уведомления об остатке места, если они доступны. Команду `php "$HOME/Bagration/public_html/admin/cli.php" storage` можно запускать через Cron: она предупреждает при 70% от 15 ГБ, занятых одним Bagration. Общий расход аккаунта с Karate и почтой проверяется в панели — PHP не видит надёжно квоту всего аккаунта.

Публикация формирует статический JSON; публичный трафик не обращается к MySQL. Медиа не входят в Git. Права на публикацию контента и организационные вопросы обработки учётных данных проверяет владелец проекта. CMS не создаёт формы сбора данных посетителей.
